# STM32 보드 등록 가이드

[STM32 보드 등록 템플릿](<STM32 보드 등록 템플릿.md>)을 보드별 파일로 복사해 작성합니다. 템플릿에는 기록할 항목과 입력 자리만 있으며, 작성 방법과 명령 예시는 이 문서에서 확인합니다.

## 기록 상태와 근거

2026-11-13 회의 결정에 따라 장비 정보가 충분한 환경의 검증을 우선합니다.
템플릿의 '진단 검증 기준 자료'에 선택한 케이스의 펌웨어·통신·정상 기준과 확인 근거를 연결합니다.
필수 자료가 미결이면 해당 케이스는 준비 보류로 기록합니다. 등록 파일만 작성했다고 실제 통신·진단 검증을
완료한 것은 아닙니다. ELF·SWD 등은 사용하는 케이스에만 필요하며, 전체 레지스터 수집을 의무화하지 않습니다.
상세 범위와 복사할 케이스 양식은 [장비 정보 기반 검증 계획](장비_정보_기반_검증_계획.md)을 참고하세요.

`<...>`로 표시한 입력 자리를 해당 보드의 값으로 바꿉니다. 확인하지 않은 값은 추정해서 채우지 않습니다.

| 표기 | 의미 |
| --- | --- |
| 미확인 | 값이나 수행 여부를 아직 확인하지 않음 |
| 미수집 | 해당 원시 데이터를 읽거나 확보하지 않음 |
| 미검증 | 기능이나 동작의 성공 여부를 검사하지 않음 |
| 미수행 | 해당 작업을 실행하지 않았음을 확인함 |
| 해당 없음 | 해당 보드나 구성에 적용되지 않음 |

팩에서 제공하는 정의와 실물 보드에서 조회한 값을 구분합니다. 타깃 팩 설치, 보드 접속, 메모리 읽기, 실제 통신은 각각 별도로 검증합니다. 조회값에는 도구, 주소와 접근 폭, 조회 시각, 원시값 또는 로그 경로를 기록합니다. 실제 동작 클록은 설정에서 계산한 값과 외부 측정값을 구분합니다.

## 전용 타깃과 타깃 팩

등록된 타깃이 있어도 이번 세션이 `cortex_m`을 사용했다면 전용 타깃 접속 성공으로 기록하지 않습니다. 팩의 Flash 알고리즘 정의가 있다는 것과 실제 쓰기·삭제 성공도 별개입니다. 보드 등록을 위해 펌웨어를 변경할 필요는 없습니다.

팩을 설치한 계정과 실제 PyOCD 실행 계정을 확인합니다. 호스트에 설치한 팩을 컨테이너에서도 바로 사용할 수 있다고 가정하지 않습니다.

보드별 선택값은 다음과 같습니다. 버전은 2026-11-05 팀 RPi에 설치한 예시이며, 실제 등록 기록에는 해당 환경의 조회 결과를 적습니다.

| 보드 | 팩 검색 인자 | PyOCD 전용 타깃 이름 | 설치 확인한 팩 예시 |
| --- | --- | --- | --- |
| NUCLEO-F103RB | `stm32f103rb` | `stm32f103rb` | `Keil.STM32F1xx_DFP` 2.4.1 |
| NUCLEO-G474RE | `stm32g474re` | `stm32g474retx` | `Keil.STM32G4xx_DFP` 2.2.0 |

타깃 팩 설치·확인은 [환경 구축 가이드](setup_guide_rpi5_diagnosis_agent.md)의 PyOCD 절차를 따릅니다.

## 메모리 맵

`show map` 또는 `target.memory_map`의 영역을 한 행씩 기록합니다. 영역 이름과 배치는 팩에 따라 다를 수 있습니다. 정의만 조회한 경우에는 실물 메모리 크기를 측정한 것으로 기록하지 않습니다.

SRAM·CCM·별칭 영역이 여러 개이면 주소가 다르더라도 같은 물리 메모리를 가리키는지 확인한 뒤 총용량을 계산합니다. Flash 페이지·섹터 크기에도 출처를 기록합니다. 특정 주소 읽기가 성공했다는 이유로 전체 영역이 유효하다고 판단하지 않습니다.

## SVD와 주변장치 레지스터

SVD는 계열 공통 정의를 포함할 수 있습니다. 목록에 나타난 모든 주변장치가 해당 MCU에 존재하거나 동작 중이라고 기록하지 않습니다. 예를 들어 팀 F103RB에서 로드한 `STM32F103xx`에는 주변장치 정의 53개가 있었지만, 이 숫자는 실물 주변장치 개수의 측정값이 아닙니다.

실시간 상태를 조회했다면 템플릿의 레지스터 표에 레지스터마다 행을 추가합니다. 조회하지 않은 항목은 `미수집`으로 남깁니다.

읽기로 상태가 바뀌는 레지스터·FIFO는 매뉴얼의 읽기 동작을 확인한 후 수집합니다. 실행 중 순차 조회한 값은 동일 시점의 스냅샷이 아닐 수 있으므로, 정지 여부와 조회 시각·순서를 함께 기록합니다. 레지스터 상태만으로 배선이나 실제 송수신 성공을 확정하지 않습니다.

## USB와 펌웨어 식별

USB 버스·장치 번호와 `ttyACM` 이름은 재연결 시 바뀔 수 있습니다. MCU UID와 ST-LINK 시리얼은 별개의 식별자입니다. ST-LINK 펌웨어 버전이 도구에 따라 다르게 표시되면 원문을 각각 보존합니다.

Flash의 초기 SP·Reset 벡터만으로 현재 펌웨어의 이름·버전이나 정상 동작 여부를 확정하지 않습니다. ELF·BIN의 경로와 해시를 기록할 때는 보드에 실제로 기록된 이미지와 일치하는지 검증 상태를 함께 적습니다.

## 기본 조회 명령 예시

아래 예시의 타깃과 프로브 ID를 등록할 실물 보드에 맞게 바꾼 뒤 실행하고, 출력은 기록의 근거로 보관합니다.

```bash
pyocd --version
command -v pyocd
pyocd pack show
pyocd list --targets
pyocd list

# G474RE를 조회할 때는 stm32g474retx로 변경합니다.
TARGET=stm32f103rb
STLINK_UID='pyocd list에서 확인한 해당 프로브의 Unique ID'
pyocd commander --no-config --target "$TARGET" --uid "$STLINK_UID" \
    --connect attach --frequency 1000000 \
    -O auto_unlock=false -O resume_on_disconnect=false \
    -c "status; show map; show peripherals; status; exit"
```

이 명령은 메모리 맵·주변장치 정의·현재 실행 상태를 조회합니다. 주변장치 레지스터의 실시간 값이나 Flash 쓰기 성공을 검증하는 명령은 포함하지 않습니다. 추가 조회·변경을 수행했다면 실제 명령과 영향 범위를 따로 기록합니다. [PyOCD 타깃 지원](https://pyocd.io/docs/target_support.html), [조회 명령 설명](https://pyocd.io/docs/command_reference.html)
