# RPi5 CAN HAT 및 GPIO 추가 측정 요약

정리일: 2026-11-16 KST.
출처: 사용자가 첨부한 「Raspberry Pi 5 + SEENGREAT RS485 Dual CAN I 장애 진단 인계 보고서」.

**현재 결론: HAT를 제거한 상태의 GPIO LOW 전압 이상 보고를 먼저 검증한다.**
RPi 또는 HAT의 하드웨어 고장, GPIO 측정값과 CAN 실패의 직접 인과관계는 아직 확정하지 않는다.
이 문서는 첨부 보고서와 기존 원격 점검 결과를 대조한 요약이다.
이번 정리 중 RPi에 재접속하거나 설정 변경·추가 계측을 수행하지 않았다.
첨부 보고서의 후속 작업 목록은 권장 사항이며 수행 완료 항목으로 취급하지 않는다.

## 1. 기존 진단에서 새로 추가된 정보

| 항목 | 첨부 보고서의 관측 | 해석 범위 |
| --- | --- | --- |
| U4 VDD·RESET# | 각각 3.3V | CAN0 칩의 정적 전원·RESET 전압 확인 |
| CAN0 SPI 배선 | SI·SO·SCK·선택 CS 도통 | 확인 경로의 명백한 단선 미발견 |
| MOSI·MISO·SCLK 상호 저항 | 1MΩ 이상 | 측정 조건에서 직접적인 저저항 단락 미발견 |
| 외부 SPI 루프백 | SPI0·SPI1 모두 송수신 일치 | 해당 시험의 데이터 경로 동작. CS·부하 조건·파형 정상은 미확정 |
| HAT 제거 후 LOW 전압 | GPIO8·11·21에서 약 1V | HAT가 붙어 있을 때만 생기는 현상으로 설명하기 어려움 |
| GPIO21 독점 요청 | 실행 중인 `gpioset` consumer 확인 | 출력 요청 유지 중에도 약 1V였다고 보고됨 |

U5 VDD·RESET의 개별 측정값은 첨부 보고서에 없다.
SPI1 외부 루프백 성공과 새 멀티미터 결과는 사용자 보고에 따른 추가 정보다.
기존 원격 시험의 원본 로그와 같은 출처로 혼동하지 않는다.

## 2. GPIO 측정 결과

아래 물리 핀 번호는 BCM GPIO 번호와 구분하기 위해 함께 적었다.
측정값은 사용자 보고서에서 가져온 것이며 이번에 다시 계측하지 않았다.

| BCM GPIO | 물리 핀 | 용도 | 출력 LOW 측정값 |
| --- | --- | --- | --- |
| 7 | 26 | SPI0 CS1 | 약 0V |
| 8 | 24 | SPI0 CS0 | 0.7~1.0V |
| 10 | 19 | SPI0 MOSI | 약 0V |
| 11 | 23 | SPI0 SCLK | 약 1V |
| 17 | 11 | SPI1 CS1 | 약 0V |
| 21 | 40 | SPI1 SCLK | 약 1V |

GPIO21에서는 출력 설정이 `op dl pn`으로 유지되면서 입력 레벨 표시는 `lo`와 `hi`가 번갈아 관측됐다.
이는 출력 설정값이 HIGH로 변경됐다는 뜻과 다르다.
`gpioset` 시험에서는 `op dl pn | lo`와 consumer=`gpioset`이 확인됐지만 전압은 약 1V였다고 한다.
디지털 입력 판독과 멀티미터 전압값은 각각 기록하고, 어느 한쪽만으로 실제 파형을 단정하지 않는다.

## 3. 현재까지의 판단

### 가능성이 낮아진 설명

- HAT 연결로만 생기는 부하 문제: HAT 제거 상태에서도 LOW 전압 이상이 보고됐다.
- `pinctrl` 명령 하나의 사용 오류: `gpioset`이 요청을 유지한 상태에서도 비슷한 전압이 보고됐다.
- CAN0 CS1 경로 하나만의 문제: CS0로 전환한 기존 원격 시험에서도 칩 응답이 없었다.
- U4의 전원 부재 또는 RESET#가 지속적으로 0V인 상태: 두 측정점에서 3.3V가 보고됐다.

### 여전히 구분해야 하는 설명

| 후보 | 필요한 구분 |
| --- | --- |
| 측정 기준·프로브·핀 번호 문제 | 같은 GND와 계측기로 정상 핀·의심 핀을 비교 |
| 외부 부하·접촉·전원 환경 | HAT·점퍼·불필요한 연결을 제거한 조건에서 확인 |
| 커스텀 커널·핀 설정·다른 접근 주체 | 별도 microSD의 기본 Raspberry Pi OS와 비교 |
| RPi의 핀·RP1 출력 경로 문제 | 정상 계측·독립 OS에서도 같은 물리 핀에 재현되는지 확인 |
| HAT 자체의 별도 문제 | RPi 출력 검증 이후 정상 호스트와 교차 시험 |

### 약 1V와 CAN 실패의 관계에 대한 주의

HAT가 없는 정적 출력 LOW에서 약 1V가 나온다는 보고는 우선 확인할 관측이다.
그러나 이것만으로 MCP2515가 SCLK·CS·SI의 LOW를 인식하지 못했다고 결론 내릴 수는 없다.
MCP2515 데이터시트의 해당 입력 LOW 상한은 `0.4 × VDD`로,
VDD=3.3V일 때 약 1.32V다. 따라서 정적 1V 자체는 이 입력 LOW 범위 안에 있다.
이는 RPi 출력 정상 판정도, 실제 SPI 파형 정상 판정도 아니다.
HIGH 전압·에지·펄스·잡음과 칩 핀에서의 실제 전압은 여전히 미확인이다.
근거: [MCP2515 데이터시트][mcp2515], 표 13-1.

## 4. 최소한의 다음 검증

### 4-1. GPIO7과 GPIO21만 먼저 비교

같은 멀티미터의 DC 전압 모드에서 검은 프로브를 동일한 RPi GND에 고정한다.
기준 GND는 예를 들어 물리 6번을 사용하고, BCM 번호와 물리 핀 번호를 대조한다.
프로브를 같은 GND 지점에 댔을 때 약 0V인지와 3.3V 전원 핀의 측정값을 먼저 확인한다.
HAT·점퍼 등 GPIO의 외부 연결은 제거한 조건을 사용한다.

GPIO7과 GPIO21을 하나씩, LOW와 HIGH를 각각 몇 초 이상 유지해 측정한다.
사용 중인 `gpioset` 버전의 명령 문법을 확인하고, 요청 프로세스가 살아 있는 동안 측정한다.
`pinctrl`과 `gpioset`으로 같은 핀의 출력을 동시에 변경하지 않는다.

| 조건 | 물리 핀 | 출력 요청 | 측정값 | consumer·핀 설정 |
| --- | --- | --- | --- | --- |
| 현재 OS | 26 / GPIO7 | LOW | 미측정 | 미기록 |
| 현재 OS | 26 / GPIO7 | HIGH | 미측정 | 미기록 |
| 현재 OS | 40 / GPIO21 | LOW | 미측정 | 미기록 |
| 현재 OS | 40 / GPIO21 | HIGH | 미측정 | 미기록 |

이 표는 같은 조건에서 LOW/HIGH를 비교하는 후속 시험용이다.
앞 절의 기존 LOW 측정 보고를 취소하거나 이미 수행한 시험을 미수행으로 바꾸는 표가 아니다.
가능하다면 다른 멀티미터로 의심 핀 한 개만 교차 측정한다.

### 4-2. 별도 microSD의 기본 OS와 비교

현재 프로젝트 카드와 설정을 보존하고 별도 microSD에서 기본 Raspberry Pi OS로 부팅한다.
GPIO21의 동일 LOW/HIGH 시험을 같은 계측기·전원·배선 조건에서 수행한다.
기본 OS에서도 재현되면 현재 프로젝트의 커널·부팅 설정만의 원인일 가능성은 낮아진다.
그때 다른 전원 공급기와 계측기를 각각 한 번씩 바꿔 측정 환경을 더 구분한다.
한 가지 조건씩 바꾸며 결과를 기록한다.

### 4-3. 그 이후에 CAN 경로로 복귀

- 정적 출력 문제가 해소되면 실제 칩 핀에서 SPI 파형과 응답을 확인한다.
- 발진 확인은 수정 발진자에 직접 프로브를 대기보다 CLKOUT의 활용 가능성을 먼저 검토한다.
- 정상 RPi 또는 정상 HAT가 있으면 교차 시험으로 범위를 좁힌다.
- GPIO와 HAT 각각에 문제가 동시에 존재할 가능성도 배제하지 않는다.

기존의 SPI 속도·모드 비교, 도통, 루프백을 같은 조건으로 일괄 반복하는 것은 우선순위가 낮다.

## 5. 설정 이력과 재개 시 확인할 사항

| 시점·출처 | 설정 또는 관측 |
| --- | --- |
| 기존 원격 CS0 시험 | SPI 활성, CAN0 `spi0-0`, CAN1 `spi1-1` |
| 첨부 보고서의 GPIO 독립 시험 | `dtparam=spi=off`, MCP2515·SPI1 overlay 비활성화 |
| 현재 RPi 실제 상태 | 이번 정리에서는 미조회 |

첨부 보고서의 `spi0.1` 오류는 CS1 시험 시점의 로그이며,
기존 원격 CS0 시험의 `spi0.0` 오류와 같은 순간의 설정으로 합쳐 해석하지 않는다.
`vc4-kms-v3d`와 `nospi10`의 존재만으로 현재 GPIO 이상 원인이라고 단정하지 않는다.
`dwc2`는 설정 섹션과 실제 적용 여부도 함께 확인해야 한다.
다시 원격 시험할 때는 실제 장착 상태·DIP·SPI 활성 상태·GPIO 요청 프로세스부터 확인한다.
GPIO 독립 시험을 이어가는 중이라면 CAN용 부팅 설정을 임의로 다시 활성화하지 않는다.
